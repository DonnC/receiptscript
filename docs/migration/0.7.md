# Migrating from 0.6 to 0.7

0.7 renames the package and makes the API smaller. Templates (`.rct` files) need no changes.
Most apps need only the import changes and the renames below.

## 1. Package and coordinates

| | 0.6 | 0.7 |
| --- | --- | --- |
| Package | `zw.co.donnclab.rct`, `zw.co.donnclab.rct.android` | `io.github.donnclab.rct` |
| Maven group | `io.github.donnclab.receiptscript` | `io.github.donnclab` |
| Artifact | `receiptscript` | `receiptscript` |

The Android classes moved from `…rct.android` into the main package, so one import covers the API:

```kotlin
import io.github.donnclab.rct.*
```

## 2. Renamed types

| 0.6 | 0.7 |
| --- | --- |
| `android.ReceiptScript` | `ReceiptScript` |
| `android.Receipt` | `Receipt` |
| `android.ReceiptDriver` | `ReceiptDriver` |
| `AssetReceiptTemplateRepository` | `AssetTemplateRepository` |
| `AssetReceiptMediaResolver` | `AssetImageResolver` |
| `ReceiptMediaResolver<Bitmap>` | `ReceiptImageResolver` (now `suspend`) |
| `android.EscPosReceiptPrinter` | `escpos.EscPosDriver` |
| `compose.ReceiptUiPreview` | `compose.ReceiptPreview` |
| core `ReceiptScript` (engine) | `RctCompiler` |
| `CompiledReceiptTemplate` | `RctTemplate` |
| core `Receipt` (blocks only) | `ReceiptDocument` |
| core `escpos.EscPosDriver` (bytes) | `escpos.EscPosEncoder`; `render` → `encode`, `renderRaster` → `encodeRaster` |
| `PlainTextDriver` | `PlainTextEncoder`; `render` → `encode` |
| `RctMeta`, `RctAlign`, `RctFontSize`, `RctFontScaleMode` | `ReceiptMeta`, `ReceiptAlign`, `ReceiptFontSize`, `ReceiptFontScaleMode` |
| `RctColumnAlignment`, `BarcodeFormat` | `ReceiptColumnAlign`, `ReceiptBarcodeFormat` |
| `RctLinter`, `RctLexerScanner` | moved to `io.github.donnclab.rct.tooling` |

## 3. Changed functions

| 0.6 | 0.7 |
| --- | --- |
| `receipt.toImageBytes()` | `receipt.toImage()` |
| `receipt.toPdfBytes()` | `receipt.toPdf()` |
| `receipt.print(driver)` | `receipts.print(receipt)`, or `driver.print(receipt)` |
| `ReceiptScript(context, driver, repository, images)` | the same order still works; prefer named arguments: `ReceiptScript(context, driver, templates = …, images = …)` |
| `repository.getTemplate(id)` | `repository.getTemplate(id, emptyMap())`: `args` no longer has a default, so the interface can be a lambda |

## 4. Removed

| Removed | Use instead |
| --- | --- |
| the nine-method core `ReceiptDriver` (`printText`, `printTable`…) | one `ReceiptDriver.print(receipt)` with a `when (block)` over `receipt.blocks`; see [Writing a driver](../guides/drivers.md) |
| `ReceiptAdapter<T>` and `Receipt.render(adapter)` | call the encoder or your function directly |
| `escpos.ReceiptPrinter(driver, connection)` | `EscPosDriver(connection)` on Android; `connection.send(EscPosEncoder().encode(document))` on the JVM |
| `RctParser`, `DefaultRctParser`, `RctTemplateEngine` and the syntax tree types | now internal; use `RctCompiler` |
| `AndroidReceiptRenderer`, `ReceiptExporter` | now internal; use `ReceiptScript.render` and the `Receipt` export functions |
| deprecated aliases `RasterReceipt`, `RasterOptions`, `ReceiptPrinter` | `Receipt`, `ReceiptOptions`, `ReceiptDriver` |
| `ReceiptPreview(document, renderer)` in Compose | render with `ReceiptScript`, then `ReceiptPreview(receipt)` |

## 5. Behaviour changes

- **Image resolver default folder.** `AssetImageResolver` now reads from `assets/receipts/` by default,
  next to the templates; 0.6 read from the assets root. Move images into `receipts/`, or pass
  `AssetImageResolver(context, directory = "")`.
- **Image resolvers suspend**, so they can load images from the network or a database. Each distinct
  reference is resolved once per render.
- **`ReceiptDriver` from your SDK can now map blocks.** `Receipt.blocks` was already there; the guide
  now documents both approaches.
- **`EscPosDriver` has a text mode.** `EscPosDriver(connection, profile, EscPosMode.TEXT)` uses the
  printer's fonts. Raster stays the default.

## 6. New

- `BluetoothPrinterConnection` and `UsbPrinterConnection` connection helpers.
- `ReceiptScript.print(templateId, data)`, which renders and prints in one call.
